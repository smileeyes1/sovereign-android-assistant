# عامل حكيم المعزول — مرشح مراجعة

هذا عامل محدود لمهام مصطنعة فقط، يعمل ببايثون ومكتبتها القياسية دون حساب نموذج أو API أو أسرار أو اتصال بالشبكة. ينفذ جمع قائمة أعداد وترتيبها فقط؛ النصوص والأوامر والمسارات والحقول الإضافية مرفوضة. لا يستقبل طلبات الجسر، ولا يعدّل الهاتف أو الإنتاج أو المستودع أو الحاكمية.

## البنية الفعلية

Work للتأسيس والمراجعة ← فرع مرشح معزول ← GitHub Actions لاختبار محدود ← عامل قواعد محلية ← queue.sqlite3 ← فاحص قبول مستقل عن عملية العامل. حالة المقصد المؤسسي تبقى في أصل سجل المشروعات؛ قاعدة هذا العامل تخص عينات shadow فقط، ولا تنافس حالة الجسر أو الهاتف.

- `worker.py`: واجهة مهام مغلقة؛ طابور SQLite متين، معرف ثابت وبصمة لكل طلب، حجز ذري بمالك ورمز fencing، ورفض النتيجة القديمة أو الخاطئة. إنهاء النتيجة والسجل في معاملة واحدة. الإعادة تعيد الموجود دون تنفيذه مرتين.
- `test_worker.py`: اختبارات سلبية وإيجابية للحقن، والصلاحيات، والتوازي، والتصادم، والفساد، وسعة الطابور، وانتهاء الحجز ومنع التكرار.
- `demo.py`: ثلاث دورات عمليات منفصلة؛ الثانية تنقطع فعلًا بخروج مضبوط ٢٣ ثم يُرصد الحجز المنتهي ويستأنف. لا يمس ملفات قائمة؛ يحتاج مجلد إثبات جديدًا.
- `acceptance.py`: يقرأ القاعدة المحفوظة قراءة فقط، ويحسب البصمات ويقارن النتائج المتوقعة وعدد الإنهاءات وميزانية المحاولات. لا يقبل مجرد تصريح العامل بالنجاح.
- `baseline.json`: هويات الحالة المستعادة، دون أسرار.

واجهتا المهام `sum` و`sort` فصل واضح عن مزود النموذج؛ يمكن إضافة موائم لاحقًا في فرع ومراجعة واختبارات جديدين. لا يوجد موائم نموذج خارجي مفعّل، ولا تنزيل نموذج، ولا استدلال عام مثبت. النموذج المحلي الكبير ليس اعتمادًا لازمًا لهذه المهام البسيطة.

## الموارد والتعافي

٢٥٦ مهمة محفوظة كحد أقصى، دون حذف القديم لفتح السعة؛ ١٠٠ عدد للمهمة، وقيمة مطلقة ≤١٠٠٠٠. حجز افتراضي ٣٠ ثانية، أقصاه ٦٠، وثلاث محاولات قبل حالة failed. كل تشغيل يعالج مهمة واحدة ثم يخرج. العمل والنتيجة داخل قاعدة واحدة؛ ملفات WAL جزء من آلية SQLite وليست سجل حالة آخر. معاملات `BEGIN IMMEDIATE` تمنع الحجز المتوازي؛ `synchronous=FULL` يحفظ الكتابة وفق ضمانات نظام الملفات. هذا ليس ضمانًا لقرص تالف أو تخزين شبكي غير موثوق.

رصد التوقف مثبت عبر خروج العملية والحجز المنتهي في الاختبار. لا يوجد حارس دائم أو daemon أو cron. استئناف المشغل اللاحق يستعيد طابورًا محفوظًا؛ بيئة GitHub Actions مؤقتة، وartifact ذو احتفاظ يوم واحد ليس قاعدة تشغيل طويلة الأمد. يلزم اختيار تخزين دائم مأذون قبل تشغيل متكرر.

## التشغيل الاختباري

```bash
python3 -m unittest discover -s sandbox/shadow_worker -p 'test_*.py' -v
python3 sandbox/shadow_worker/demo.py --root /tmp/hakim-shadow-proof-new
python3 sandbox/shadow_worker/acceptance.py --root /tmp/hakim-shadow-proof-new
```

Workflow جديد لتدقيق PR فقط: `contents: read`، دون secrets أو OIDC أو صلاحيات كتابة، أفعال مثبتة بـSHA، مشغّل Ubuntu قياسي، ومهلة خمس دقائق. لا تعديل للعامل القديم أو لأي workflow ميداني. نجاحه يعطي `PASS_SHADOW_ONLY`؛ الإنتاج والتشغيل الدوري يبقيان `NO_GO`.

## أبواب الاعتماد

يلزم نجاح اختبارات المصدر على نفس SHA، وثلاث دورات خارج Work مع انقطاع واستئناف دون تكرار، وفحص مستقل. حتى بعد ذلك يظل النجاح خاصًا بالمهام المصطنعة. الدمج والإصدار والنشر والتشغيل الدوري أو الهاتف يحتاج تحققًا إضافيًا وتفويضًا جديدًا محددًا.

Railway بديل مشروط بفحص ميزانية واستدامة وتخزين دائم؛ لم يُنشأ مورد ولم تُقرأ قيم الأسرار ولم تُقبل التعديلات المعلقة. Android طرف اختياري مجمد، وليس مضيفًا مضمونًا. Plus لا يستعمل بوصفه رصيد API.

نقطة الرجوع: حذف الفرع المرشح أو تجاهله وفق إجراء مراجعة مأذون؛ لا تغيير أصل main أو الجسر أو البيانات القائمة. PRs الأمنية السابقة ٣١٠–٣١٢ محفوظة وغير مدمجة. هذا المسار لا يرفع أي NO-GO سابق.
